# Temperature 和 Sampling：模型如何决定下一个 Token

在学习大模型调用时，我遇到了两个经常一起出现的概念：**Temperature（温度）**和 **Sampling（采样）**。

我一开始把 Temperature 理解成概率本身，把 Sampling 理解成截取一部分最接近标准的数据。后来我把它们分开理解：

> **模型先给候选 Token 计算概率，Temperature 调整概率分布，Sampling 再根据这个分布选择下一个 Token。**

## 模型是怎样生成回答的？

大模型不是一次性把整句话从数据库里找出来，而是逐步生成 Token。每生成一个 Token，模型都会结合当前上下文，预测下一个 Token 可能是什么。

例如，用户问：“中国的首都是哪里？”模型可能为下一个 Token 形成类似这样的概率分布：

```text
北京  0.80
上海  0.08
南京  0.05
广州  0.04
其他  0.03
```

模型选出“北京”之后，会把它放回上下文，再继续预测后面的 Token。这样不断循环，最终生成完整回答。

这些数字不是模型从数据库里查到的答案，而是模型根据训练得到的参数和当前上下文，对候选 Token 做出的概率估计。

## Temperature：调整概率分布的“温度”

Temperature 不是一个“答案相关度分数”，也不是概率本身。它更像一个概率分布调节器，用来改变候选结果之间的差距。

### Temperature 较低

最高概率的候选会更加突出：

```text
北京  0.94
上海  0.03
南京  0.02
广州  0.01
```

模型会更倾向于选择最可能的 Token，因此回答更稳定、保守、可重复。

### Temperature 较高

概率分布会更加平均：

```text
北京  0.45
上海  0.22
南京  0.18
广州  0.15
```

其他候选也有更多机会被采样，输出会更丰富、更有变化。

因此可以先这样理解：

- Temperature 低：选择更集中，输出更稳定。
- Temperature 高：选择更分散，输出更多样。

但 Temperature 高不等于更聪明，Temperature 低也不等于绝对正确。它主要控制生成过程中的随机性和多样性。

## Sampling：根据概率选择 Token

Sampling 就是根据概率分布，从候选 Token 中选择一个作为下一步输出。

最简单的方式是每次都选择概率最高的候选，这叫 Greedy Decoding：

```text
北京  0.50  ← 永远选择第一名
上海  0.25
东京  0.15
广州  0.10
```

这种方式很稳定，但可能让回答缺少变化。另一种方式是按概率随机抽取：概率高的候选更容易被选中，但概率较低、仍然合理的候选也有机会出现。

可以把它类比成抽签：北京有 50 个签位，上海有 25 个签位，东京有 15 个签位，广州有 10 个签位。抽到谁不是完全固定，但概率更高的候选更容易被抽到。

## Top-k Sampling：只保留前 k 名

Top-k 的意思是只保留概率最高的 k 个候选，再在它们里面采样。

原始候选：

```text
北京  0.50
上海  0.25
东京  0.15
广州  0.10
```

如果设置 `top_k = 2`，只保留：

```text
北京  0.50
上海  0.25
```

“东京”和“广州”不会参与这一步选择。Top-k 不是截取“最接近标准的数据”，而是截取概率排名靠前的候选 Token。

## Top-p Sampling：保留累计概率达到 p 的候选

Top-p 又叫 nucleus sampling。它不是固定保留几个候选，而是从概率最高的候选开始累加，直到累计概率达到设定的 `p`。

例如：

```text
北京  0.50
上海  0.25
东京  0.15
广州  0.10
```

当 `top_p = 0.75` 时，前两个候选的累计概率刚好达到 0.75，因此保留“北京”和“上海”。

Top-p 的特点是候选数量会根据当前分布变化：如果模型非常确定，候选集合可能很小；如果模型比较犹豫，候选集合可能更大。

## 为什么大模型需要 Sampling？

如果模型永远只选第一名，回答会很稳定，但也可能出现：

- 表达方式重复
- 创意不足
- 每次回答几乎一样
- 生成内容过于保守

Sampling 允许模型在合理候选之间保留一些变化，因此更适合创意写作、故事生成、广告文案和头脑风暴。

不过，随机性也可能带来不稳定。对于需要严格执行的任务，过高的随机性可能导致格式变化、工具参数错误或分类结果不一致。

## 不同任务如何选择？

可以先用这个经验表理解：

| 任务 | Temperature 倾向 | 原因 |
| --- | --- | --- |
| JSON 信息提取 | 较低 | 希望字段稳定、格式一致 |
| 意图分类 | 较低 | 希望同类输入走同一分支 |
| Tool Calling | 较低 | 工具名称和参数需要可靠 |
| 代码生成 | 较低 | 希望逻辑和格式更稳定 |
| RAG 问答 | 较低 | 尽量围绕检索资料回答 |
| 普通聊天 | 中等 | 兼顾稳定和自然 |
| 故事创作 | 较高 | 希望表达更丰富 |
| 头脑风暴 | 较高 | 希望获得更多不同方向 |

这只是经验方向，不是绝对规则。真正效果还会受到模型能力、Prompt、上下文和任务本身的影响。

## 把整个过程串起来

一次生成可以简化成下面这样：

```text
当前上下文
    ↓
模型为候选 Token 打分
    ↓
形成概率分布
    ↓
Temperature 调整分布的集中程度
    ↓
Top-k / Top-p 筛选候选范围
    ↓
Sampling 选择一个 Token
    ↓
把 Token 放回上下文，继续下一轮
```

## 我的总结

> **模型负责预测候选 Token，Temperature 调整概率分布，Top-k 或 Top-p 缩小候选范围，Sampling 负责从候选中选择下一个 Token。**

结构化输出、分类和工具调用更需要稳定，所以通常倾向较低的 Temperature；创意写作和头脑风暴需要变化，因此可以适当提高随机性。
