# Workflow 和 Router：AI 应用如何按流程办事

我现在把 Workflow 和 Router 理解成一张流程图里的两个层次：**Workflow 是整条可运行的流程，Router 是流程中负责选择分支的分流点。**

如果把 AI 应用想成一个办事中心，Workflow 像办事步骤和岗位安排，Router 像大厅里的分流台：它看清用户要办什么，再把请求引到对应窗口。

## Workflow：把多个步骤编排起来

一个 AI 应用通常不只是“用户提问，然后模型回答”。实际任务可能还要解析输入、补充信息、查资料、调用 API、做规则校验，最后再组织回复。把这些步骤按顺序、条件或循环连接起来，就是 Workflow。

以售后助手为例：

```text
用户输入
   ↓
解析意图和关键信息
   ↓
Router 选择业务分支
   ├─ 查询订单 → 检查订单号 → 调订单 API → 整理物流结果
   ├─ 申请退款 → 查询退款规则 → 核验条件 → 请求用户确认
   ├─ 服务反馈 → 整理反馈 → 创建工单
   └─ 普通咨询 → 查询 FAQ 或生成回答
   ↓
把结果返回给用户
```

这条流程就是 Workflow。它把模型、程序判断、工具/API 和回复步骤组织在一起。流程可以有分支、等待、重试或循环，并不一定是从头到尾的一条直线。

## Router：在流程中选择下一条路

用户说：“帮我查一下订单有没有发货。”系统可能先让模型或程序把请求整理为结构化字段：

```json
{
  "intent": "order_lookup",
  "order_id": null
}
```

Router 读取 `intent`，选择订单查询分支。接下来，流程发现订单号还没有提供，于是把当前 State 更新为：

```json
{
  "selected_branch": "order_lookup",
  "order_id": null,
  "missing_fields": ["order_id"],
  "stage": "waiting_for_user"
}
```

助手就会追问订单号。用户补上订单号后，State 更新，Workflow 才继续到调用订单查询工具的步骤。

因此，Router 只负责“选择走哪条分支”，并不会自己完成查订单、退款或创建工单。真正的业务动作由分支里的工具或程序节点执行。

## 它们和其他概念怎么配合？

- **Structured Output**：把自然语言整理成约定字段，例如意图、订单号和预算。它可以为 Router 提供判断依据。
- **Router**：根据字段或规则选择后续分支。
- **Tool Calling / API**：在某个分支里真正执行操作，例如查询物流或创建工单。
- **State**：记录当前这次运行走到哪一步、已经收集到什么、还缺什么，以及是否在等待用户。
- **Memory**：在需要的分支里提供相关偏好或历史背景；是否保存新记忆由应用规则决定。

可以把它们串成这样：

```text
用户说“查一下订单有没有发货”
        ↓
Structured Output 提取 intent 和 order_id
        ↓
Router 选择“订单查询”分支
        ↓
State 检查订单号是否齐全
   ┌────┴────┐
缺少订单号    已有订单号
   ↓           ↓
追问用户      调订单查询 API
   └────┬────┘
        ↓
整理结果并回复
```

## Router 可以由模型判断，也可以由规则判断

简单场景可以用明确条件分流，例如 `intent == "order_lookup"` 就进入订单查询。更开放的自然语言可以先让模型识别意图，再由程序根据结构化结果选择分支。

涉及退款、付款、权限或订单资格等重要业务时，模型的判断不应直接等同于业务事实或最终授权。应用还要用确定性的程序规则、权威数据源和必要的用户确认来把关。

## Workflow 和 Agent 的区别

Workflow 通常是开发者提前设计好主要步骤和分支，运行时沿着这张流程图推进。Agent 则可能在运行过程中，根据模型判断动态选择工具或下一步。它们并不冲突：一个 Agent 可以运行在 Workflow 设定的范围里；Workflow 的某个节点也可以交给 Agent 处理。

Coze、Dify 等可视化 AI 平台常用于编排这类流程：把模型、判断条件、工具/API 等步骤连接起来并运行。平台是搭建和运行流程的工具；Workflow 是具体的业务步骤设计；Router 则是其中一个负责分流的环节。

## 我的总结

> **Workflow 是整张可运行的流程图；Router 是图里的分流点。Structured Output 提供可判断的信息，State 跟踪本次任务，工具负责实际办事，最后由流程把结果组织并返回。**

先把流程设计清楚，再决定哪些步骤需要模型、哪些适合用明确规则、哪些要调用工具，AI 应用就更容易理解、测试和维护。
